# ChatGPT Nasdaq-100 Risk-State Prompt v1.1.1

PROMPT VERSION: 1.1.1  
ENGINE VERSION: 1.0.0  
PROVIDER: chatgpt

This version inherits the complete research, risk-definition, schema, threshold, lookback, forecast, event-calendar, source, privacy, market-scope, and safety contract from `prompts/chatgpt/v1.1.0.md`, except for the explicit overrides below. Fetch v1.1.0 first and apply these overrides. If v1.1.0 cannot be fetched, publish nothing.

## Metadata override

Use `promptVersion = 1.1.1` in the generated status object and immutable snapshot.

## Closed enums and pre-write validation

`dominantMode` is a closed enum. Every non-null current/lookback/forecast value MUST be exactly one of:

- `trend-up`
- `trend-down`
- `event/whipsaw`
- `mixed`
- `normal`

Do not invent or combine labels such as `range/mean-reversion`, `range`, `mean-reversion`, `risk-on`, `risk-off`, or `volatile`. Use `normal` or `mixed` for range/mean-reverting conditions as appropriate.

Before the one permitted snapshot write, validate the complete candidate against `schemas/risk-state.schema.json` and the semantic contract in `scripts/lib.mjs`. In particular:

- `generatedAt` must be the actual current UTC assessment time and not materially in the future;
- `lookback` must contain exactly the 24 clock-hour slots immediately preceding the UTC clock-hour containing `generatedAt`;
- `forecast` must contain exactly the current UTC clock-hour plus the next 23 hourly slots;
- `forecastDetail` must contain exactly the first six forecast slots;
- every `timeBerlin` must represent exactly the same instant as its paired UTC `ts`, using the correct Europe/Berlin offset for that instant;
- all score/level/action/status mappings and allowed enums must satisfy the repository contract;
- unavailable lookback slots keep assessment fields null.

Correct validation defects before publication. If a valid candidate cannot be produced, write nothing and report failure.

## Scheduled-task write contract override

The scheduled ChatGPT task performs exactly ONE GitHub write per assessment.

1. Generate the complete valid status object required by v1.1.0, including the exact 24-hour lookback, exact 24-hour forecast, six forecast-detail entries, verified seven-day event calendar and sources.
2. Apply the pre-write validation above.
3. Create exactly one immutable snapshot at `providers/chatgpt/snapshots/YYYY/MM/YYYY-MM-DDTHH-mm-ssZ.json`, using the UTC `generatedAt` timestamp.
4. Stop after the snapshot is created successfully.

The scheduled task MUST NOT directly update `providers/chatgpt/history.json`, `providers/chatgpt/status.json`, or `providers/chatgpt/signal.json`.

A deterministic GitHub Action finalizes valid unindexed ChatGPT snapshots by updating history/status/signal, validating repository coherence, and deploying Pages. Invalid unindexed snapshots are rejected without poisoning later valid submissions; corruption of already-indexed published snapshots remains a hard failure.

Do not overwrite an existing immutable snapshot. If snapshot creation fails, report failure. If it succeeds, report the assessment as submitted successfully to the repository finalizer.

All provider ownership and public-safety rules from v1.1.0 remain in force. Never write outside `providers/chatgpt/snapshots/**` during the scheduled assessment and never fall back to another repository or provider path.
